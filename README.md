# Mist Overhaul

Расширение подменяет статичные портреты NPC в [Mist](https://www.mist-game.ru)
на зациклённые анимации.

Игра берёт портреты с `https://i.mist-game.ru/npc/<имя>.jpg`, расширение
перехватывает эти запросы через `declarativeNetRequest` и отдаёт вместо них
локальный webp. Подмена работает везде, где картинка встречается: у
квестодателя, в списках, в бою.

Персонажам, для которых есть видео, достаётся анимация; остальным — статичный
апскейл в том же разрешении. Первый кадр анимации сам по себе полноценная
картинка, так что браузер, который webp понимает, а анимацию в нём не тянет,
покажет её как обычный портрет.

Портрет в игре выводится не как `<img>`, а фоном у `div.userpic` с
`background-size: auto`, поэтому картинка 2x без правки показалась бы
увеличенным углом, размноженным плиткой. Это чинит `npc.css` — единственный
content script, цепляется только за `[style*="/npc/"]`, аватарки игроков не
трогает.

## Установка

**Юзерскрипт (обновляется сам).** Открыть `mist-overhaul.user.js` в браузере с
Tampermonkey → «Установить». Обновление приезжает само: Tampermonkey сверяет
`@version` по `@updateURL`.

Все 22 портрета скрипт складывает в **Cache Storage** сразу при первом заходе в
игру — после `load`, чтобы не отбирать канал у самой игры. Дальше они берутся
оттуда (`blob:`), и в сеть никто не ходит. Обычного кеша браузера для этого мало:
jsDelivr отдаёт `max-age=604800`, то есть через неделю пойдёт перепроверка, да и
чистка истории его сносит. У Cache Storage срока нет, а старые версии портретов
скрипт вычищает сам — их адресов больше нет в таблице.

`@resource` не подошёл: Tampermonkey держал картинки с первой установки и не
перекачивал даже после смены ссылок — в игре он отдавал сборку q82, когда на CDN
давно лежала q95, и «проверить обновления» на это не влияло.

**Расширение (без обновлений).** `chrome://extensions` → **Режим разработчика** →
**Загрузить распакованное** → папка `extension/`. Делает ровно то же, но подменой
запросов, а не правкой DOM, и не обновляется: Chrome распакованные расширения не
обновляет в принципе. Ставить что-то одно — вместе они дублируют работу.

## Публикация

Юзерскрипт и картинки раздаёт jsDelivr прямо из репозитория, отдельный хостинг
не нужен. После `git push` в `main`:

```bash
./publish.sh "новые портреты"   # сборка + коммит + push
```

Инвалидация кеша встроена в имя файла: `caravaneer.30518e4e.webp`, где хвост —
хеш содержимого. Поменялась картинка — поменялось имя, и новая приходит мимо
любого кеша; не поменялась — адрес прежний, и качать нечего. Поэтому и ветка
`@main` в ссылках безопасна: под одним адресом никогда не окажется другое
содержимое.

Так вышло не сразу. Ветка без хеша не годится: кеш jsDelivr живёт до 12 часов, а
`purge.jsdelivr.net` отрабатывает через раз — на проверке из 22 файлов разом
обновились шесть, остальные ещё отдавали прошлую версию, хотя purge отрапортовал
`finished`. Привязка к тегу, а потом к коммиту это чинила, но заставляла
перекачивать все 54 МБ из-за одного персонажа и требовала двух коммитов подряд.

Сам скрипт лежит на `raw.githubusercontent.com`: он крошечный, кеш там ~5 минут,
и обновление находится сразу. Версия — время сборки, так что растёт всегда, даже
если поменялся только код.

## Пересборка

```bash
python3 -m venv .venv && .venv/bin/pip install numpy
.venv/bin/python build.py       # видео -> extension/npc/*.webp, gif/*.gif, rules.json
.venv/bin/python check_loop.py  # проверка, что стык петли не виден
```

Логику подмены проверяет `test/fixture.html` — копия игровой разметки: подмена,
запасной слой, масштаб, смена персонажа без перезагрузки и предзагрузка всех 22
портретов. Ждать пять `PASS`. Файл нужно отдать по http (на `file://` не поедет
`<script src>`) и с новым query-параметром, иначе браузер подсунет закешированный
скрипт:

```bash
python3 -m http.server 8731    # затем открыть /test/fixture.html?cb=1
```

Список персонажей берётся из `Mist characters/Original/`, каждому нужен
`Upscaled/<имя>.*`. Новый персонаж оживает так: положить
`Mist characters/Video/<имя>.mp4` (кроп 9:16 из `Upscaled/<имя>.png`) и
перезапустить `build.py` — `rules.json` соберётся сам, готовые webp не
пересчитываются. Если имя файла с видео не совпадает с именем персонажа,
добавить его в `ALIASES` в `build.py`.

## Как получается петля

1. По уменьшенным в серое кадрам строится матрица попарных расстояний, из неё
   выбирается пара «начало / конец» с минимальным разрывом при максимальной
   длине петли (не короче 4 с).
2. Первые 10 кадров петли перетекают из кадров, идущих *за* её концом, —
   после перемотки в начало движение продолжается без рывка.
3. Кадры вкладываются обратно в апскейл персонажа с растушёвкой боковых стыков:
   видео снято кропом 9:16, а игре нужны пропорции 181x267, и недостающие
   полосы по бокам берутся из статичного апскейла.

Выход — 362x534 (2x от игрового размера), 24 fps.

## gif

`gif/` собирается тем же прогоном, но в расширение идёт webp: gif ограничен
256 цветами на всю анимацию, на этих артах даёт бандинг по градиентам неба и
весит втрое больше. Чтобы вернуть gif, поменять расширение файла в
`build()` и в правилах.
